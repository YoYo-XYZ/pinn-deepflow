# Shared harness with break-and-migrate outputs and allowlisted escapes for benchmarks

Comparison suites under `benchmarks/` duplicate training, sampling, evaluation, and plotting logic instead of using the public DeepFlow API. We rework every in-scope suite into a thin wrapper over one shared harness (shared configuration, shared domain builders, shared reporting), migrate outputs without backward compatibility, and permit non-canonical code only through explicit allowlisted flex markers.

## Considered Options

- **Per-suite clones with incremental dedup (rejected):** keeping each suite self-contained preserves local control, but domain or sampling changes fan out to many clones and reviewers cannot tell canonical use from hand-rolled workarounds. This is the problem statement itself.
- **One flat helper module versus three harness concepts (picked three):** a single shared module would tangle configuration, domain building, and reporting changes together. Three concepts (config replacing per-suite config clones; domain builders for Burgers, channel, cavity, and cylinder-with-obstacle including the shared perimeter-weighting rule; reporting via pickle-style persistence plus evaluator and visualizer plots with markdown reports) give one seam per concept and let each suite declare only what varies.
- **Byte-compatible or dual-write output migration (rejected):** keeping old `.npz` fields, checkpoint dicts, and custom-plot outputs readable alongside new ones doubles the reader and writer surface and lets stale artifacts linger as pseudo-source. Break-and-migrate moves persisted models to native pickle-style outputs, derives metrics from evaluation result dictionaries and loss histories, and renders plots through visualizer calls, updating per-suite readers once with no transition period.
- **Free-form escapes or a total raw-code ban (rejected both):** free-form raw torch and matplotlib reintroduce unaudited bloat; a total ban is unfair where raw code is legitimate. The allowlist permits exactly four escapes, each with a marker comment and reason: the external competitor suite stays raw for a fair baseline, quantum model construction may use its quantum backend import, precision comparisons may use device synchronization and dtype casts with timing, and custom plotting is allowed only for a demonstrated visualizer gap. Everything else must be canonical.
- **Reference handling: always-cached versus always-FEM (picked neither):** always-cached ground truth drifts from the library, while always-FEM breaks offline use. Canonical FEM solve plus reference evaluation is primary; cached numeric archives serve only as an explicit offline fallback when the FEM backend is unavailable.

## Consequences

Per-suite modules shrink to variant declarations (formulation choice, model type, sampling choice, precision setting) delegating domain construction, train-one (Adam then L-BFGS via the simple-loss helper), evaluation, and reporting to the harness. Output shapes change, so comparison readers move to the new outputs. Adding a variant means writing one thin model-construction wrapper. Orchestrator entry points keep their suite-selection behavior but delegate to the harness. Visualizer and evaluator gaps found during migration are noted, not fixed here, and the public DeepFlow API itself is untouched.
